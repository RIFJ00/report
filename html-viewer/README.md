# 省庁記事ビューワー（開発版）

閲覧画面: `/html-viewer/`

このフォルダは独立して追加されており、既存の `/blog/` `/blogimport/` `/xpost/` およびトップページは変更しません。

## 現在の実装
- `articles.json` から公開記事を読み込む（初期状態は空配列）
- タイトル・本文の文字列検索、省庁・分野による絞り込み
- 公開日（新旧）、省庁名、登録順で並び替え
- サムネイル表示、画像が無い場合は省庁名で代替表示
- 左に一覧、右に記事プレビュー。スマートフォン対応
- 出典記事と生成HTMLへのリンク
- `?id=記事ID` による個別記事選択
- 記事HTMLのプレビューは sandbox iframe に隔離（JavaScript不許可）

## 記事フィード（articles.json）

```json
[
  {
    "id": "ministry-20261124-001",
    "title": "記事の正式タイトル",
    "ministry": "文部科学省",
    "category": "教育",
    "sourceUrl": "https://www.mext.go.jp/",
    "publishedAt": "2026-11-24",
    "publishedAtSource": "source",
    "imageUrl": "",
    "summary": "記事の概要",
    "text": "記事本文（プレーンテキスト）",
    "html": "",
    "htmlUrl": "",
    "status": "published"
  }
]
```

`publishedAt` は原則として元ページの公表日を使う。公表日不明時のみ既存仕様に従ってアップロード日を採用し、`publishedAtSource: "upload"` と記録する。生成HTMLは `html`（直接埋込み）または `htmlUrl`（別ページのURL）で提供できる。公開済みの `status: "published"` のみ閲覧画面に表示する。

## ローカル記事編集（2026-11-24追加）

- `/html-admin/` は記事データをブラウザ内で整えるための**試験ツール**。Firebaseへの書込や公開処理は一切行わない。
- 既存の `articles.json` をファイル選択で読み込み、記事を追加・更新し、JSONを書き出す。
- `html-viewer/article-utils.mjs` が日付・出典URL正規化とURL重複排除を担当する。
- ローカル確認用テスト: `node --test html-viewer/article-utils.test.mjs`（Node.js 20以降想定）。この環境では実行結果未確認。
- 実運用の管理画面にする前に、Firebase Authentication、サーバー側の権限検査、Firestore/Storageルール、HTMLサニタイズ、監査ログを必ず実装する。
- ブラウザの `file://` 直接起動では ES Modules が動かない環境があるため、ローカルHTTPサーバーかステージング環境で検証する。
- 現時点では公開日と記事本文の自動抽出は**未実装**。省庁別の取得処理と接続後に対応する。

## URL入力型HTML生成ツールとの接続（2026-11-24）

- 既存の生成ツールが出力したHTMLファイルを `/html-admin/` で読み込み、**HTMLから情報を抽出**を押すと、タイトル・元ページ公開日・代表画像・本文テキストを取得する（ローカルのみ）。
- 出典URLは**手入力で指定**する。HTML内の相対リンク・画像URL解決に使う。
- 公開日は `article:published_time`、公開日meta、`time[datetime]`、JSON-LD `datePublished` から探索する。更新日 `dateModified` は公開日とみなさない。
- 和暦・年月日表記・スラッシュ区切りを日付として正規化する。ただし省庁ページ独自の書式や本文中の「令和○年○月○日」を網羅していないため、検出結果は必ず目視確認する。
- 代表画像がない場合は既存の省庁名サムネイルを使用する。
- プレビュー用HTMLはスクリプト・iframe・フォーム等を取り除き、表示側の sandbox iframe でもJavaScriptを無効化している。ただしこれは厳密なサニタイズ保証ではなく、本番の不特定HTMLを扱う場合は、十分なHTMLサニタイザー、CSP、別オリジン配信等を検討する。
- `html-viewer/article-utils.test.mjs` のユニットテストはGitHub Actionsの `html-viewer-test.yml` でPR時に実行する設定を追加した（成功結果は別途確認が必要）。
- 各省庁のURLを入力するだけで自動クロールする機能はまだ接続していない。HTMLファイルの取り込みとフィードへの書き出しを行う中間実装である。

## Firebase統合の試験実装（2026-11-24）

- `html-viewer/firebase-config.json` は **enabled: false** / **firebaseConfig: null** が初期値。運用環境とルールの安全確認が完了するまで変更しないこと。
- Firebase有効時、閲覧側は専用の `ministryArticles` コレクションに `status == published` のクエリだけを実行する。無効時は従来通り静的 `articles.json` を読む。
- `html-admin/firebase-admin.mjs` はGoogleログイン後、Firebase Authのサーバー発行カスタムクレーム `rifjAdmin: true` を再確認する。**クレームをブラウザから設定する機能は存在しない。**
- 管理画面からの読み込み・保存はユーザー操作で明示的に実行し、Firebase自動保存は行わない。既存記事の読み込みと保存は別々の操作。
- ログイン用Google認証プロバイダー・承認ドメイン、FirebaseのプロジェクトIDとFirestoreの設定は実環境での検証が必要。
- `firestore.rules.example` は専用コレクションへのルール断片であり、**既存プロジェクトのルール全体と置き換えてはいけない**。管理者用カスタムクレームは信頼できる管理側環境で付与する。
- 管理画面 `/html-admin/` はブラウザでアクセスできる構成だが、Firestoreへの書き込みはルールで制限される。本番では別途管理ページ自体の配信制御、CSP、監査ログ、誤操作防止、レビューを検討する。
- Firestore 1ドキュメントのサイズ制限に備え、書き込み前に記事データが大きすぎないかチェックしている。長文記事の分割保存は今後の課題。
- **今回の作業は作業ブランチのみ。Firebaseプロジェクト設定、認証設定、Firestoreルール、本番データ、Hostingデプロイは変更していない。**

## Firestore権限テスト（2026-11-24追加）

- `html-viewer/tests/` に独立したFirestore Emulator用ルール・アクセス権テストを追加した。
- テストは公開記事の閲覧、下書き・非公開記事の拒否、一般利用者の書き込み拒否、管理者の正当な操作、不正な記事データの拒否を対象にする。
- `html-viewer/tests/firestore.rules` は **テスト専用の独立ルール**。本番への上書きは禁止。既存Firestoreの設定に適用する場合は、別の `firestore.rules.example` をベースに現行の全ルールと統合・審査する必要がある。
- GitHub Actionsの `firestore-emulator` ジョブは `demo-rifj-html` のローカルEmulatorのみで実行し、本番Firebaseプロジェクトには接続しない。
- 実環境での管理者アカウント設定・認証・画面操作のE2Eテストは未実施である。

## 公開状態の一連の検証と書き込み保護

- Emulatorテストに **下書き→公開→非公開** の遷移と、一般閲覧クエリへの表示・非表示を追加した。
- 本文更新時に元記事の公表日情報を保持するケースも検証対象とした。
- Firebaseへの一括書き込みは**全記事を事前検証してから**処理する。無効な長文記事が途中に混じっていても、その理由で先行記事だけが保存されることを防ぐ。
- Firestoreの書き込み上限に対応するため、350件ずつバッチ処理する。350件を超える場合は複数バッチなので、通信障害等が起きた際には一部バッチだけが成功する可能性がある。失敗時はFirebaseから再読込して状態を確認する。
- 「自動反映」は公開状態の記事をFirebaseから読み出す方式を指し、現在は閲覧ページの再読み込み時に反映する。リアルタイム購読は未実装。

## HTML解析テストと公開前の制約（2026-11-24）

- 省庁記事HTMLからの公開日・代表画像・本文抽出について、jsdomを利用した実HTML構造のテストを追加した。
- 更新日を公開日と誤認しないこと、JSON-LDの和暦、日付不明時のアップロード日代替、相対リンク解決、危険な埋込要素の除去を検証対象とする。
- HTMLの危険な埋込み要素、インラインイベント、style、srcsetなどは削除する。ただし現状の処理を完全なサニタイザーとみなしてはならない。本番公開前にはサニタイザーによる許可リスト方式、外部リソース・URLの扱い、CSPを追加確認する。
- ブラウザで実行するHTML抽出はローカルファイル経由のみ。省庁URLそのものをブラウザから取得するAPI・サーバー側のクロール処理は未接続。
- 公開は `/html-viewer/`、管理は `/html-admin/` とするが、Firebase Hostingの実際のサイトID・デプロイ元が確定するまで本番公開しない。
